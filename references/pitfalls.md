# 踩过的坑（建库前先读，能省几小时）

来源：2026-10 ~ 2026-11，Windows 桌面版豆包 Agent，单个窗口累积 2346 轮、24.8 MB 轨迹的实战。

## 一、找原始数据

1. **桌面端 SQLite 几乎都是加密的。**
   `%LOCALAPPDATA%\<App>\User Data\sdk_storage\<id>\` 下有 `messages.db` / `im.db` / `settings.db`，看着像聊天库。
   实测：文件头是随机字节（`16 A8 2E DF...`），不是 `SQLite format 3`，sqlite3 打开直接报 `file is not a database`。
   **先读前 16 字节再动手**，别写一堆解析代码再发现打不开。

2. **文件被占用时读不了。**
   Copy 一份到临时目录再读，别原地开。

3. **真正的金矿在 Agent 自己的工作目录。**
   `...\.doubao\agent_mode\workspace\.sessions\<sessionId>\agents\<agentId>\system\trajectory.jsonl`
   这是逐行 JSON，含 `role`（user / assistant / tool）、`content`、`tool_calls`。全量原话都在。
   同一个目录还有 `assignment.md`（本轮任务上下文），体积可能很大。

4. **会话接口比本地库可靠。**
   若有 `get_conversation_messages(conversation_id, turn_limit, cursor)` 这类接口，返回带 `sequence` 和时间戳，最准。缺点是翻页慢（一次 5–20 轮），2346 轮要上百次调用。

## 二、导出

5. **先原样备份，再加工。**
   24.8 MB 原文件复制一份；抽对话卷是另外生成的新文件，绝不能覆盖原件。

6. **抽对话时把 tool 结果全丢掉。**
   18998 行里 7605 行是 tool 输出，占体积但没对话价值。只留 user / assistant 的文本，24.8 MB 会缩到约 3.4 MB，7 卷，能直接读。

7. **按轮聚合，不按消息。**
   user 起一轮，其后所有 assistant 文本归这一轮。这样"第 N 轮"是稳定坐标，方便引用。

## 三、时间归位

8. **trajectory.jsonl 没有时间戳。**
   字段只有 role / content / tool_calls。想按天切，只能从正文里正则抽 `YYYY-MM-DD` 取众数。
   **结论：给"日期线索"，别声称精确到天。** 要精确就得走接口翻页。

## 四、检索

9. **关键词精确匹配会被虚词带偏。**（最坑的一个）
   第一版直接 `if kw in text`，搜"喜欢吃"命中 1 条（就是用户刚问的那句），能用。
   但用户拿整句来问（"唐玄那个兵器到底是怎么定的"），就废了：切出的 4-gram 全是"到底是怎 / 底是怎么"，排在真答案前面。

10. **解法：只留纯实字片段。**
    虚字表（的/了/是/吗/怎/着/来/过/说/想/要/会/能/这/那/个/我/你/他/在/就/也/都/和/跟/把/被/给/对/不/没/还/再/很/太/最/更/到/儿……）：
    - 片段首尾是虚字 → 丢
    - 片段中间有虚字 → 丢
    只用纯实字片段检索，噪音立刻掉一大截。

11. **加 IDF，越常见越不值钱。**
    `score += len(g) * log((N+1)/(df[g]+1))`；`df > N*0.30` 的片段直接不用。

12. **整句原话命中直接置顶。** 用户复述原话时，`+1000` 让它排第一。

13. **需要 jieba 吗？** 不必须。实字片段 + IDF 的组合，在 2000 轮规模上够用，还少一个依赖。

## 五、让"自动想起来"真的发生

14. **文件库不会自己生效。**
    模型不会开机就翻盘。唯一不靠自觉的通道：平台的跨会话偏好 / 记忆注入条目。
    往那里写一条"新会话先读 `<库>/00_开机必读.md` 和 `01_流水.md`"，每次会话开始自动带。
    容量有限（一条几十字），所以要写的必须是**最关键的入口**，不是全文。

15. **别指望第三方记忆框架。**
    mem0 / Letta(MemGPT) / Zep 都是给"自己写 agent 的人"用的：靠 agent 主动调 `add()/search()`，或者替换整个运行时。
    已经在某个平台里跑的 agent，装了也接不进它的上下文窗口——等于脖子上挂个 U 盘。
    **能借的是它们的思路：核心层常驻 + 归档层按需调页 + 混合检索打分。**

16. **"记得"和"知道分量"是两回事。**
    原话是字符串；真正像人，是给每条结论标注"为什么定这条"（当时的争执、被否掉的方案、谁拍板的）。
    没有这层，三年后翻到也只看到一句干巴巴的话。

## 六、信任

17. **编造的代价大于遗忘。**
    用户能容忍"想不起来"，不能容忍"先编一版、被听出不对、再道歉"。
    编一次，整段对话的可信度归零。铁律：翻不到就说没聊过。

18. **别把档案丢给用户。**
    "这是 7 个文件你自己看"——等于把活推回去。用户要的是"我问你，你答"，翻是 Agent 的事。
