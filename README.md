# agent-memory-keeper

> 你的 AI 每次开新对话都像第一天上班——不是它“忘了”，是它的上下文被压缩了。
> 这个 skill 给它一套磁盘上的记忆。

## 它解决什么

主流 Agent 的会话上下文有限。聊长了，早期原话被摘要替换，细节蒸发；用户看到的就是“每次都像新同事”、“昨天的都不记得”。

**关键认知：压缩丢的是上下文，不是数据。** 原话通常还在本地轨迹或平台接口里，能捞回来；但如果不落盘，下次照样失忆。

## 四层结构

| 层 | 装什么 | 写法 |
|---|---|---|
| 原始层 | 逐日 / 逐轮原文 | 只追加，永不删、不覆盖 |
| 结论层 | 已拍板的口径、能力边界、否决清单 | 一事一行，改了覆盖 |
| 起点层 | 这活怎么起的、第一天接了什么任务 | 只增不改 |
| 状态层 | 现在卡在哪 | 覆盖式，只留最新 |

压缩只发生在结论层。三个月后原始还在，日常读的量却很小。

## 安装

把整个目录放进你的技能目录（如 `.user_skills/` 或 `.claude/skills/`），保持 `SKILL.md` 在目录根。

## 用

```bash
python scripts/search_memory.py --src <trajectory.jsonl 或目录> "他刚才说的那句话"
```

把用户整句话丢进去即可，不需要提炼关键词：脚本自己拆实字片段、按稀有度（IDF）加权、整句原话命中置顶。

## 详细内容

- `SKILL.md` —— 六步工作流 + 四条回答铁律
- `references/pitfalls.md` —— **18 条实测坑**，包括：桌面端 SQLite 是加密的怎么一眼认出、轨迹文件没有时间戳怎么归位、关键词检索被“到底是怎”带偏怎么治、第三方记忆框架（mem0 / Letta）为什么接不上已经跑在平台里的 Agent

## 一句话铁律

**翻不到就说“没聊过”，不许先编一版、被听出不对再道歉。** 编一次，后面每句都被怀疑。
