# agent-memory-keeper

> 你的 AI 每次开新对话都像第一天上班——不是它“忘了”，是它的上下文被压缩了。
> 这个 skill 给它一套磁盘上的记忆。

**关键词**：豆包 / Doubao / Agent 长期记忆 / 记不住 / 上下文压缩 / 会话失忆 / 跨会话记忆 / context compaction / memory

---

## 自检：你的 Agent 是不是这个毛病

- 说“我从来没跟你说过这个”，但你明明说过
- 你问以前的事，它先道歉，再给一个大概的答案
- 它把你“忘了”归因成“你是不是开了新窗口”
- 同一个约定你要讲第二遍、第三遍
- 聊到某个人物、参数、口径，前后两次说法不一样

中三条以上，就是这个病，往下看。

## 它解决什么

主流 Agent 的会话上下文有限。聊长了，早期原话被摘要替换，细节蒸发；用户看到的就是“每次都像新同事”“昨天的事都不记得”。

**关键认知：压缩丢的是上下文，不是数据。** 原话通常还在本地轨迹或平台接口里，能捞回来；但不落盘，下次照样失忆。

所以这个 skill 不是教 Agent “学会记”，而是给它一个**在外面存着、压缩碰不到的硬盘**。

## 这不是给谁的（先说清楚，省得白折腾）

**不给**：想扩上下文窗口的、想接 API 的、要上生产环境的、期待克隆下来一键就好的。

**给**：用豆包桌面版（或其他封闭客户端）聊了一两个月、开始觉得它“犯傻”的个人用户。不需要编程基础，会双击 bat、会复制路径就够。

真实成本：建库 + 导一次历史，认真做大概一两个小时；之后每天写几行，几秒钟。

## 四层结构

| 层 | 装什么 | 写法 |
|---|---|---|
| 原始层 | 逐日 / 逐轮原文 | 只追加，永不删、不覆盖 |
| 结论层 | 已拍板口径、能力边界、否决清单 | 一事一行，改了覆盖 |
| 起点层 | 这活怎久起的、第一天接了什么任务 | 只增不改 |
| 状态层 | 现在卡在哪、下一步 | 覆盖式，只留最新 |

要点：**压缩只允许发生在结论层**。原始层三个月后还在，但日常读的量很小——开机只读 3 KB 的入口文件，不够才往下翻。

## 跟已有方案什么关系（别以为是重复造轮子）

这块地早有人占了，而且是工业级的：

| 项目 | 星数 | 做法 |
|---|---|---|
| mem0 | ~6.9 万 | 即插即用记忆层，要 agent 主动调它的 API |
| TencentDB Agent Memory | ~3.1 万 | L0 原始 / L1 原子 / L2 场景 / L3 画像 |
| OpenViking（火山） | ~4.3 万 | 上下文数据库，记忆 + RAG + 技能 |
| hindsight | ~6.2 万 | 跨 agent 长期记忆 |
| cognee | ~3.3 万 | 知识图谱式记忆 |

你会发现四层跟腾讯那套 L0–L3 很像。**不是抄，是两条路走到了同一个地方**——一个结构能被两边各自推出来，说明它版是对的。

**差在哪：这些方案都要求 agent 能调 API、能挂 hooks。封闭客户端（比如豆包桌面版）两样都没有。** 所以它们装不上去，不是不好用，是接不进去（见 `pitfalls.md` 里 mem0 / Letta 那几条）。

这条就没办法了：只能读本地轨迹、写普通文件、把开机指令钉进跨会话偏好。**这条路没人大规模写过，所以这个仓库存在。**

## 安装

把整个目录放进你的技能目录（如 `.user_skills/` 或 `.claude/skills/`），保持 `SKILL.md` 在目录根。

建议另外建一个记忆根目录（例：`D:\记忆库\`，下面 `00_入口.md` / `01_状态.md` / `02_定死的结论.md` / `03_每日摘要/` / `10_会话原文/`）。存哪都行，关键是**不要在系统盘**，也别放在技能目录里（更新技能时容易被一起覆盖）。

## 用

```bash
python scripts/search_memory.py --src <trajectory.jsonl 或目录> "他刚才说的那句话"
```

把用户整句话丢进去，不要提炼关键词：脚本自己拆实字片段（带“的/是/怎/到”这类虚字的片段一律丢弃）、按稀有度（IDF）加权、整句原话命中置顶。

设计理由：用户真实说话是“上礼拜那个降分辨率的事最后怎么说的”，直接拿这串做关键词，会被“到底是怎/底是怎么”这类碎片带偏。

跑出来一条没命中，就**直说没聊过**，不要顺着往下编。

## 豆包专属的那些事

如果你用的也是豆包桌面版，下面这些能直接用：

**轨迹文件位置**（你的原始数据全在这，不加密、可以直读）：

```
C:\Users\<用户名>\AppData\Local\Doubao\User Data\Default\.doubao\agent_mode\workspace\.sessions\<会话ID>\agents\<agentID>\system\trajectory.jsonl
```

字段：`{role, content, tool_calls, tool_call_id, image_link_list}`，role 为 `user` / `assistant` / `tool`，**没有时间戳**（日期只能从正文里的日期字符串取众数，只能算“线索”）。

**别去碰的那几个库**：同目录 `User Data\sdk_storage\...\` 下的 `messages.db`、`im.db`、`settings.db` 是**加密**的。判断方法：文件头不是 `SQLite format 3`，而是随机字节，`sqlite3` 打开会报 `file is not a database`。别浪费时间。

**导出建议**：原样备份 jsonl 一份（别动），再按 user 起轮聚合成卷、丢弃 tool 噪音，按 200 KB 左右切卷。一份 25 MB 的轨迹，纯对话能压到 3 MB 左右，人可以直接翻。

## 换到别的 Agent

四层结构不用改，只有两处要动：

**1. 数据入口**：`scripts/search_memory.py` 里的 `load_turns()`。现在写的是“遇到 `role == user` 开新轮，`assistant` 归入当前轮，`tool` 丢弃”。你的 agent 轨迹格式不一样，就改这一个函数，其余逻辑（拆词、IDF、排序）全部可复用。

**2. 拿不到轨迹怎么办**——按下面顺序退：

- 平台有导出 / 读会话接口 → 写个拉取脚本，定期落盘（最可靠）
- 只有当前上下文可读 → **每轮结束就把原文追加到当日文件**（这时主流做法，不优雅但不会丢）
- 什么都拿不到 → 让 Agent 自己在结束时写摘要；它中途被压缩就写不出来，这个方案没有保证
